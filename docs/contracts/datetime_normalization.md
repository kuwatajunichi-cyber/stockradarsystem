# Datetime Normalization Contract

## 目的

日時・タイムゾーン差異による計算不整合を防ぐため、正規化責務を統一する。

## 契約

- 日時比較・アンカー計算は、UTC基準の timezone-naive 正規化後に行う。
- 正規化の実装責務は単一モジュールに集約し、他モジュールで再実装しない。
- `datetime64[ns]` 解像度へ正規化し、`us/ns` 差による比較ゆらぎを回避する。

## 禁止

- 指標モジュール内での `tz_convert` / `tz_localize` の直接実装。
- 正規化手順のコピペ。

## 検証

- timezone aware/naive 混在データで契約テストを実施する。
- 監査テストで「禁止トークンの再出現」を検知する。
