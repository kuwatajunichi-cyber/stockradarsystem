# ADR-002: 日次 MACD ヒストグラムおよびチャート寄り状態ラベルの設計

## 状態

採用（2026-04。実装は本記録の契約に従う。未実装部分はフェーズ分割可）

## 文脈

- 調査候補の抽出および定量指標の出力において、日次データ上で MACD ヒストグラムの水準および「反転」「ゼロ付近での滞留」に近い状態を機械可能な形で付与したい。
- [dc-002](../decision-candidates/dc-002-rise-mid-down-universe.md) や [dc-004](../decision-candidates/dc-004-fake-signal-detector.md) と整合しつつ、**投資助言・売買シグナルではなく**フラグ／数値出力に留める（`README.md` のスコープと一致）。
- チャート画面上の自動スケーリングにより、人手が「ゼロ付近でヨレている」と感じる条件は **ヒスト絶対値のみでは再現されにくく**、銘柄間の単一の絶対閾値（通貨建ての単一 eps）だけでは意味がぶれる。

## 決定概要

### スコープ

1. **第1フェーズ**: 日次・銘柄ごとに、算出基準日（アンカー）から遡って **直近 K 営業日の MACD ヒスト値**を算出し、既存コア指標 CSV（`indicators_YYYYMMDD.csv` 系）に **ワイド列**で載せる。
2. **第2フェーズ以降**: 同じ算出列を入力として、ゼロラインクロス、ゴーストクロス、[dc-004](../decision-candidates/dc-004-fake-signal-detector.md) で述べるダマシの素地になりうる状態の **チャート読み寄り** のフラグまたは区分列を付与する。
3. 実装レイヤでは **pure 関数**（I/O 分離）、ジョブは既存パターンに合わせ `compute_indicators_for_core` 相当の経路への組み込みを想定する。

### MACD／ヒストの定義契約（再現性）

- **入力**: 既存 Yahoo キャッシュ銘柄 CSV と同一の終値系列（インデックスは営業日の `DatetimeIndex`）。`Close` が調整済み／未調整のどちらかは **キャッシュ側の約束と一致**させ、ADR および README で一言明記する。
- **標準パラメータ**: ヒストのみを主成果とする場合のデフォルトは **MACD（12, 26, 9）**。パラメータが変わる場合は **列名またはマニフェスト**で識別可能にする。
- **式**: MACD と Signal は標準定義とし、**ヒスト h_t = MACD_t - Signal_t**。
- **EMA の実装**（pandas `ewm` 等）は **`adjust` 等で分岐があるため、ひとつの約束を選び単体テストで固定する**。第三者チャートサービスとの完全一致より **リポ内一貫性** を優先し、ずれがある場合は本 ADR とテスト値で説明する。

### アンカーと履歴要件

- 他指標（RS など）と同様、**算出基準日**は `resolve_run_anchor_date` に相当する単一のアンカー営業日とする（`nth_business_anchor` で遡って K 本取得）。
- アンカー当日のヒストが NaN になる初動区間および **ヒスト算出に最低限必要な本数不足** は、列を欠損とし、`flags` または集計可能性のためのフラグで **明示**する（「静かに失敗しない」）。
- `ensure_core_cache` の **required_days** は現状、`max(RS 窓, z 窓) + buffer` 基準であり多くは十分だが、MACD が成立する下限（例: slow と signal より十分長いバー数を見込む）と **K 日分さらに遡る分** を `required_days = max(従来, macd_min_bars)` のように取り込むか、不足時のみ欠損とするかを **実装時に明示**する。

### 成果物形状（CSV）

- **第1フェーズ**: ワイド列 `macd_hist_0`（アンカー当日）、`macd_hist_m1` … など **過去側へ営業日オフセット**が分かる名前にする。
- 任意: 検証やデバッグ用に `macd_line` / `signal` を同じ命名体系で載せられるが、公開列の増加と取捨選択は別 Issue でよい。
- 「長いテーブル専用の別ファイル」も分析向きには妥当だが、既存パイプライン（`core_indicators_csv` が `indicators_*.csv` のみをコアとして探索）との整合では **当面はコア CSV 拡張**を既定とする。

### 「ゼロ付近」判定（チャートの見た目に寄せる）

固定の **通貨建ての絶対閾値のみ**を唯一の「eps」と呼ぶ単一定義には **しない**。代わりに、**直近 W 営業日のヒストのレンジ**に対する相対しきい値を主契約とする。

- `R_W = max(h) - min(h)` を同一銘柄・同一ジョブ内の窓 W のヒストについて計算する。
- **近零判定の例**: `|h_t| / max(η, R_W) < p`
  - `p`: 小さめの比率（例 5〜15% 領域をチューニング）。
  - `η`: 分母の床（ヒスト変動が極めて小さいときの数値暴走防止）。
- `W` はチャート画面上の視野に対応させ、**20〜60 営業日程度**を初期候補とする。
- 「横ばい」のうちノイズ（符号のフラップのみ多い状態）を抑える場合は、`p` と **別条件との AND**（例: フラップ頻度）を任意で載せられる余地を残す。

### 反転（ゼロラインクロス）

- **上向きクロス**: 前営業日 `h_m1 <= 0` かつ 当日 `h_0 > 0` を基本形とする。**下向き**は鏡。極微小ノイズのみ除外したい場合は最小のフェイルソフトのみ任意で追加し、複雑な中間状態はフラグ側に渡す。

### ゴーストクロス

用語が曖昧なため **タイプ分割**して契約する。

| タイプ | 概要 | メモ |
|--------|------|------|
| **A（ヒスト主）** | ゼロを跨いだが直後も相対近零であり「本筋のクロス」とは見ない | フラグのみで済ませやすい |
| **B（ライン視）** | MACD とシグナル線がニアミス | **ライン値の列**があること前提 |

第1フェーズがヒストのみの場合、**タイプ B** は延期または別フラグセットと明示する。

### 反転前夜（クロス尚未）

ヒストのみで近似する場合の例:

- アンカーで `h_0 < 0` のとき、負の領域でゼロへ **`h` が単調増加する日が複日連続**する。
- または **単調増加** と **相対近零** を組み合わせる。

同一営業日に、複数のラベルが同時に立ちうる（相互に排他的ではない）。

### 非目標（Non-goals）

- トレンド転換の予測や最適パラメータ一本化（dc-004 と整合）。
- リアルタイム約定単位での更新。
- 「買い／売り」など助言表現の列名・説明文（フラグは中性的な名前にする）。

## 代替案（却下・保留）

| 代替 | 評価 |
|------|------|
| 銘柄横断で同一の絶対閾値のみ | 却下。**相対パラメータ（p, W, η）** を既定とする |
| ヒストの列なし・ラベルのみ開始 | 却下。**先に直近 K 本のヒスト**を載せ、その上でラベル |
| 別テーブルのみ出力 | 保留相当。分析向きだが二重保守が増える。**当面はコア CSV ワイド拡張**を既定 |

## 影響範囲

- `src/stockradar/indicators/`: MACD／ヒストの pure、必要ならフラグ関数。
- `compute_indicators_for_core`: 列追加、`nan_count` / `slots_per_row`、`required_days` との両立。
- `ensure_core_cache` / `ensure_index_cache`: `macd_min_bars` が required_days に載る場合の契約更新。
- テスト: `pytest tests/` に pure の単体テスト（外部 API なし）。
- README / user-facing: 指標一覧は実装と同期。
